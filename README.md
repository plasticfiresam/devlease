# devlease

Реестр аренды iOS-симуляторов и Android-эмуляторов на одной машине.

[English version](README.en.md)

Десять агентов на машине запускают по симулятору, а когда свободного нет, заводят новый: диск
заполняется устройствами, память — эмуляторами, которые никому не нужны. `devlease` держит
фиксированный пул, отдаёт каждое устройство одному агенту за раз на срок, который агент называет
сам, ставит остальных в очередь и даёт человеку одну страницу, где всё видно и можно почистить.

```sh
devlease run --kind ios --profile phone --ttl 20m --boot -- sh -c 'flutter test -d "$DEVLEASE_SERIAL"'
devlease status
devlease serve        # http://127.0.0.1:7788
```

## Установка

```sh
uv tool install git+https://github.com/plasticfiresam/devlease
# или: pipx install git+https://github.com/plasticfiresam/devlease
```

Нужен Python 3.11 или новее, других зависимостей нет. Для реальных устройств нужны macOS с Xcode
(`xcrun simctl`) и Android SDK (`ANDROID_HOME`, по умолчанию `~/Library/Android/sdk`).

## Как это работает

- **Фиксированный пул.** Пул — это устройства, которые уже есть в системе (`devlease status`
  пересканирует их не чаще раза в минуту). Агенты устройства не создают, а просят об этом (см.
  ниже).
- **У аренды есть срок.** `--ttl` обязателен и ограничен для всей машины (по умолчанию 30 минут,
  большее значение отклоняется). `renew` продлевает аренду, каждый раз не больше чем на потолок.
  Аренда также заканчивается, когда умирает процесс из `--pid`, а `run` останавливает свою команду,
  когда срок аренды вышел.
- **Честная очередь.** Если подходящего свободного устройства нет, `acquire` ждёт, один раз
  сообщает, кто что держит и сколько ещё, и обслуживает ожидающих по порядку: более поздний агент
  может взять устройство, только если оно не подошло бы никому из тех, кто пришёл раньше. `--wait`
  ограничивает ожидание (по истечении код 75, как у `heavy`).
- **Лимит одновременно работающих устройств.** `limit_ios` и `limit_android` (по умолчанию по 2)
  ограничивают число арендованных устройств, поэтому память не выходит за предел при любом размере
  пула.
- **У Android-эмуляторов свои порты.** Аренда сообщает serial (`emulator-5554`), один AVD никогда
  не запускается дважды.
- **Освобождение выключает устройство** (`simctl shutdown`, `adb emu kill`), в том числе при
  истёкшей аренде.
- **Запись сериализована** через `BEGIN IMMEDIATE` в файле SQLite (WAL) в `~/.cache/devlease`
  (`DEVLEASE_DIR` переносит его), поэтому все рабочие копии и агенты делят один реестр.

Коды выхода: `0` успех, `2` неверные аргументы, `3` в пуле нет подходящего устройства, `4` запрос
на создание ждёт человека, `75` ожидание истекло, `124` (`run`) срок аренды вышел.

## Устройства, которых нет в пуле

```sh
devlease request-device --kind android --name Pixel_9_API_36 --profile pixel_9 --os 36 --reason "..."
```

Если подходящее устройство уже есть, возвращается его id. Иначе устройство создаётся сразу, пока
в пуле меньше `max_devices_<kind>` устройств (по умолчанию 8 iOS и 4 Android) и на диске свободно
не меньше `min_free_gb` (по умолчанию 20 ГБ). Сверх этого запрос ждёт человека на веб-странице или
в `devlease requests approve|reject <id>`. Если нет системного образа Android, запрос завершается
ошибкой с командой `sdkmanager`, которую нужно выполнить: образы для агента не скачиваются.

## Принуждение

Правило в промпте легко пропустить, поэтому добавьте хук. Для Claude Code в
`~/.claude/settings.json`:

```json
{ "hooks": { "PreToolUse": [ { "matcher": "Bash",
  "hooks": [ { "type": "command", "command": "devlease hook pretool" } ] } ] } }
```

Хук блокирует создание и клонирование устройств (`simctl create`, `simctl clone`,
`avdmanager create avd`, `flutter emulators --create`) и любую команду, которая работает
с устройством пула (`boot`, `install`, `launch`, `flutter run -d`, `adb -s`, `emulator -avd`
и подобные), пока никто не арендовал это устройство. Команды, которые начинаются с `devlease`,
проходят. Если сам реестр сломан, хук пропускает команду. Хук не знает, какому агенту принадлежит
аренда, а только то, что она есть, и читает текст команды целиком, поэтому id устройства,
спрятанный в скрипте, он не заметит, а упоминание запрещённой команды в тексте (например,
в heredoc с документацией) примет за вызов.

## Веб-страница

`devlease serve [--port 7788]` отдаёт одну страницу на `127.0.0.1`: каждое устройство с состоянием,
держателем, оставшимся временем и занятой памятью; очередь; запросы на создание с кнопками Approve
и Reject; память и диск хоста; кэши (Xcode DerivedData и DeviceSupport, Gradle, кэш сборки Android,
uv, npm, недоступные симуляторы) с размерами и кнопкой Clean. Если кэшем пользуется его инструмент
(например, Gradle при открытой Android Studio), сначала спрашивается подтверждение.

Страница предлагает только фиксированный список кэшей и не принимает от браузера ни путь, ни
команду; для POST нужны особый заголовок и локальный `Host`.

Чтобы страница работала постоянно как LaunchAgent в macOS: `devlease service install` (и
`uninstall`).

## Настройки

`devlease config` показывает числа, `devlease config max_ttl 1800` меняет одно. Ключи: `max_ttl`
(секунды), `limit_ios`, `limit_android`, `max_devices_ios`, `max_devices_android`, `min_free_gb`,
`port`.

## Для агентов

Навык в [`skills/devlease`](skills/devlease/SKILL.md) объясняет агенту, как всем этим пользоваться.
Подключите эту папку в каталог навыков агента. Навык написан по-английски: его читает агент.

## Разработка

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Тесты запускают настоящие CLI, хук и веб-сервис на фиктивном списке устройств.
